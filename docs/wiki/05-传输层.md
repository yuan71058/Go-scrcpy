# Go-scrcpy Code Wiki — 传输层（pkg/transport）

`pkg/transport` 管理与 scrcpy-server 的底层 TCP socket 通信，使用 **reverse tunnel** 模式（Android 设备主动连接 PC）。

## 包结构

```
pkg/transport/
├── connection.go  # Listener (reverse tunnel) + Connection (三通道)
├── reader.go      # ProtocolReader — 二进制协议读取器
└── writer.go      # ProtocolWriter — 二进制协议写入器
```

## 连接架构

```
PC (Listener)                    ADB reverse tunnel              Android (Server)
    │                                                               │
    │  tcp:127.0.0.1:27183  ←───  localabstract:scrcpy  ────────  │  Video Socket
    │  tcp:127.0.0.1:27184  ←───  localabstract:scrcpy_1  ──────── │  Audio Socket
    │  tcp:127.0.0.1:27185  ←───  localabstract:scrcpy_2  ──────── │  Control Socket
```

## 类型定义

### Listener — Reverse Tunnel 监听器

```go
type Listener struct {
    ln          net.Listener  // TCP 监听器
    videoConn   net.Conn      // 视频通道连接
    audioConn   net.Conn      // 音频通道连接
    controlConn net.Conn      // 控制通道连接
    mu          sync.Mutex
}
```

**构造函数：**

```go
func NewListener(port int) (*Listener, error)
```

- 创建 TCP 监听器在 `127.0.0.1:<port>`
- `port=0` 时自动分配

**核心方法：**

| 方法 | 说明 |
|------|------|
| `GetPort()` | 获取实际监听端口 |
| `Accept(video, audio, control, timeout)` | 依次接受 Android 的 1~3 个 socket 连接 |
| `Close()` | 关闭监听器和所有连接 |

**Accept() 流程：**

```
1. 设置 deadline = now + timeout
2. 如果 video=true，Accept() 第一个连接 → videoConn
3. 如果 audio=true，Accept() 第二个连接 → audioConn
4. 如果 control=true，Accept() 第三个连接 → controlConn
5. 清除 deadline
```

- 每个 Accept 使用 `SetDeadline()` 实现超时控制
- 连接顺序由 scrcpy-server 决定：video → audio → control

### Connection — 三通道连接

```go
type Connection struct {
    VideoConn   net.Conn  // 视频通道
    AudioConn   net.Conn  // 音频通道
    ControlConn net.Conn  // 控制通道
    mu          sync.Mutex
}
```

**构造函数：**

```go
func NewConnectionFromListener(l *Listener) *Connection
```

从 Listener 获取已建立的三个 socket 连接。

**方法：**

| 方法 | 说明 |
|------|------|
| `Close()` | 关闭所有通道连接（置 nil） |
| `IsClosed()` | 检查是否所有通道已关闭 |

### ProtocolReader — 协议读取器

```go
type ProtocolReader struct {
    r   io.Reader  // 底层读取器
    buf []byte     // 内部缓冲区 (4KB)
}
```

**构造函数：**

```go
func NewProtocolReader(r io.Reader) *ProtocolReader
```

**读取方法：**

| 方法 | 读取大小 | 字节序 | 说明 |
|------|----------|--------|------|
| `ReadFull(n)` | n 字节 | — | 读取完整 n 字节，使用 `io.ReadFull` |
| `ReadByte()` | 1 字节 | — | 读取单个字节 |
| `ReadUint16BE()` | 2 字节 | BigEndian | 读取 uint16 |
| `ReadUint32BE()` | 4 字节 | BigEndian | 读取 uint32 |
| `ReadUint64BE()` | 8 字节 | BigEndian | 读取 uint64 |
| `ReadInt32BE()` | 4 字节 | BigEndian | 读取 int32 |
| `ReadInt64BE()` | 8 字节 | BigEndian | 读取 int64 |
| `ReadInt32Native()` | 4 字节 | LittleEndian | 读取 int32（native byte order） |
| `ReadInt64Native()` | 8 字节 | LittleEndian | 读取 int64（native byte order，手动位运算） |
| `ReadString(n)` | n 字节 | — | 字符串 |
| `ReadUTF8String()` | 4+len 字节 | BigEndian | 带 4 字节长度前缀的 UTF-8 字符串 |

**注意：** 帧元数据中的 PTS 使用 **native byte order**（Android 上通常为 LittleEndian），手动实现位运算读取。

### ProtocolWriter — 协议写入器

```go
type ProtocolWriter struct {
    w io.Writer  // 底层写入器
}
```

**构造函数：**

```go
func NewProtocolWriter(w io.Writer) *ProtocolWriter
```

**写入方法：**

| 方法 | 写入大小 | 字节序 | 说明 |
|------|----------|--------|------|
| `Write(data)` | n 字节 | — | 写入原始数据 |
| `WriteByte(b)` | 1 字节 | — | 写入单个字节 |
| `WriteUint16BE(val)` | 2 字节 | BigEndian | 写入 uint16 |
| `WriteUint32BE(val)` | 4 字节 | BigEndian | 写入 uint32 |
| `WriteUint64BE(val)` | 8 字节 | BigEndian | 写入 uint64 |
| `WriteInt32BE(val)` | 4 字节 | BigEndian | 写入 int32 |
| `WriteInt64BE(val)` | 8 字节 | BigEndian | 写入 int64 |
| `WriteString(s, length)` | length 字节 | — | 写入固定长度字符串（右侧填充零） |
| `WriteUTF8String(s)` | 4+len 字节 | BigEndian | 写入带长度前缀的 UTF-8 字符串 |
